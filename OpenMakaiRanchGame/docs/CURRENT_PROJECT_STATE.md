## Working architecture, source-verified

`GameRoot` is the autoload composition root. Startup constructs `DataRegistry`, a fresh in-memory `SaveState`, local settings and services. Bootstrap opens Main Menu. Continue loads a slot; New Game resets state and opens the existing creation UI. `Game.tscn` hosts the scene-authored management shell. `SceneRouter` navigates shell screen IDs, not 3D zones.

`DataRegistry` loads JSON into typed Resources first, then has seeded fallbacks. Current save schema is **14**, not 11. `SaveService` uses System.Text.Json, string enums, size/depth limits and temporary-file replacement. `GameRoot.LoadSlot` rebuilds state-bound services. Capturing a service or CharacterState forever in a future avatar would be incorrect after load/new game.

Scheduling is currently character-ID-to-job-ID assignment, not spatial daily routines. Time advances through Morning, Afternoon, Evening and Night by explicit commands, not a continuous clock. `DailySettlementService` applies work output, costs, events, growth and day rollover. `RanchService.ApplyJobOutput` mutates stockpile and returns gold to its caller; it must not also be triggered by future animation callbacks.

Existing economy/shop, equipment, inventory, ranch, bond, research, pets, adventure/combat and mature-related state/services remain intact. Their exact call flow and limitations are documented in `audit/simulation-map.md`. Presence and smoke success do not prove every UI action, edge case or original formula.
